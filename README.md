# TravelMate

Туристическая платформа на Django REST Framework. Туристы ищут и бронируют туры, гиды создают туры, а AI узнаёт место по фото, отвечает на вопросы и составляет маршрут поездки.

## Запуск

1. Создать и включить виртуальное окружение (Windows):

   ```
   python -m venv .myvenv
   .myvenv\Scripts\activate
   ```

2. Установить библиотеки:

   ```
   pip install -r requirements.txt
   ```

3. Получить ключ на https://console.groq.com/keys, создать файл `.env` рядом с `manage.py` и записать туда этот ключ. Пример лежит в `.env.example`. Без ключа работает всё, кроме AI.

   ```
   GROQ_API_KEY=your-key-here
   ```

4. Создать таблицы и админа:

   ```
   python manage.py migrate
   python manage.py createsuperuser
   ```

5. Запустить сервер:

   ```
   python manage.py runserver
   ```

6. В админке http://127.0.0.1:8000/admin/ поставить своему суперпользователю роль `Админ`.

7. Добавить демо-данные (необязательно). Команду можно запускать снова: дублей не будет.

   ```
   python manage.py seed_data
   ```

8. Открыть сайт: http://127.0.0.1:8000/

## Запуск в Docker

Скопировать `.env.production.example` в `.env.production`, заполнить и запустить. Сайт откроется на порту из `FRONTEND_BIND`, по умолчанию 80:

```
docker compose up -d --build
```

Запросы идут так: `frontend` (nginx с сайтом) → `backend-nginx` (nginx перед Django, отдаёт `/media/`) → `backend` (Django и WebSocket). Адрес `/` показывает сайт, а `/api/` показывает Swagger. База и файлы хранятся в томах `data` и `media` и не пропадают при обновлении контейнеров.

На общем сервере порт открыт только для его nginx: в файле `.env` рядом с `docker-compose.yml` указано `FRONTEND_BIND=127.0.0.1:8021`. Процессор сервера ARM, поэтому образы собираются с `--platform linux/arm64`.

## Сайт

Сайт написан на обычных HTML, CSS и JavaScript, без библиотек, и работает на том же сервере, что и API:

- `templates/index.html` — страница сайта;
- `css/style.css` — оформление, дневная и ночная темы;
- `static/js/translations.js` — тексты на русском, английском и таджикском;
- `static/js/api.js` — запросы к серверу и токены;
- `static/js/ui.js`, `forms.js`, `cards.js` — общие функции, поля форм и карточки;
- `static/js/pages/` — страницы сайта, каждая группа в своём файле;
- `static/js/app.js` — шапка, подвал и выбор страницы по адресу;
- `static/img/` — фотографии, `static/fonts/` — шрифты: сайт работает и без интернета.

Сообщения об ошибках от сервера и демо-данные написаны на русском: на три языка переведён только интерфейс.

Команда `seed_data` добавляет фотографии демо-местам и турам, в том числе уже созданным. Авторы и лицензии снимков с Wikimedia Commons перечислены на странице сайта «Авторы фотографий». Шрифт Manrope распространяется по лицензии SIL Open Font License.

## Демо-пользователи

Пароль у всех: `Demo-Pass-492`. Эти пользователи нужны только для учёбы и проверки.

| Логин | Роль |
|---|---|
| `demo_tourist1` ... `demo_tourist6` | турист |
| `demo_guide1` ... `demo_guide3` | гид |
| `demo_admin` | админ |

Команда создаёт по 10 записей каждой модели. Броней 13: 10 подтверждённых нужны для отзывов, а ещё 3 показывают статусы `pending` и `cancelled`. Сообщения чата и планы поездок в демо-данных написаны заранее, а не AI.

## Как проверить API

Swagger: http://127.0.0.1:8000/swagger/

1. Выполнить `POST /auth/login/` и скопировать `access`.
2. Нажать **Authorize** и ввести `Bearer <access>`.
3. Вызывать нужные адреса.

Токен `access` живёт 30 минут, `refresh` живёт 1 день.

## Роли

| Роль | Что может |
|---|---|
| `tourist` | смотрит туры, бронирует, пишет отзывы |
| `guide` | создаёт и меняет свои туры, подтверждает брони своих туров |
| `admin` | может всё, добавляет места |

При регистрации можно выбрать `tourist` или `guide`. Роль `admin` выдаётся только через админку.

## Адреса API

Все адреса начинаются с `/api/`.

| Адрес | Что делает |
|---|---|
| `POST auth/register/` | регистрация |
| `POST auth/login/` | вход, возвращает `access` и `refresh` |
| `POST auth/refresh/` | новый `access` по токену `refresh` |
| `POST auth/logout/` | выход, `refresh` попадает в чёрный список |
| `GET, PATCH auth/me/` | мой профиль |
| `places/` | места. Фильтры: `?city=`, `?search=` |
| `tours/` | туры. Фильтры: `?city=`, `?price_min=`, `?price_max=`, `?days=`, `?search=` |
| `favorites/` | моё избранное |
| `bookings/` | брони. Фильтр: `?status=` |
| `POST bookings/{id}/confirm/` | гид подтверждает бронь |
| `POST bookings/{id}/cancel/` | турист отменяет свою бронь |
| `reviews/` | отзывы. Фильтр: `?tour=` |
| `GET chat/conversations/` | мои диалоги с туристами или гидами |
| `POST chat/conversations/` | открыть диалог по брони: `{"booking": 1}` |
| `GET chat/conversations/{id}/messages/` | последние 50 сообщений. Более ранние: `?before=` |
| `POST chat/conversations/{id}/messages/` | отправить текст, фото или голосовое (`kind`: `text`, `image`, `voice`) |
| `POST chat/conversations/{id}/read/` | отметить сообщения прочитанными |
| `DELETE chat/messages/{id}/` | удалить своё сообщение |
| `GET chat/messages/{id}/file/` | фото или голосовое, только для участников диалога |
| `POST ai/photo-search/` | поиск места и туров по фото |
| `POST ai/chat/` | вопрос AI-консультанту |
| `GET ai/chat/history/` | моя история чата |
| `POST ai/trip-plan/` | составить маршрут |
| `GET ai/trip-plans/` | мои сохранённые маршруты |

Места и туры с картинками отправляются как форма (`multipart/form-data`), а не как JSON.

## Сообщения между туристом и гидом

Турист и гид переписываются, если между ними есть бронь: кнопка «Написать» находится в карточке брони. Можно отправить текст, фото и голосовое сообщение. Админ чужую переписку не видит.

- Новые сообщения, значок непрочитанных, «печатает…» и «в сети» приходят по WebSocket `ws://127.0.0.1:8000/ws/chat/` (библиотека Django Channels). `python manage.py runserver` запускает его сам благодаря Daphne.
- Вход по WebSocket: первым сообщением отправить `{"type": "auth", "token": "<access>"}`. Текст отправляется как `{"type": "message", "conversation": 1, "text": "Привет"}`.
- Фото и голосовые лежат в папке `private_media/`. Прямой ссылки на них нет, файл получают только участники диалога.
- Микрофон браузер разрешает только на `https://` и на `127.0.0.1` или `localhost`.
- Сообщения между вкладками идут через память процесса, поэтому сервер должен работать одним процессом. Для нескольких серверов в `CHANNEL_LAYERS` нужен Redis.

Тесты чата: `python manage.py test chat`.
